## Обязательные архитектурные границы

```text
Decision Provider → Action → GameActionRunner → GameEngine → GameState
```

- GameEngine — единственный арбитр игровых правил.
- AI выбирает Action, но не изменяет state.
- GameActionRunner сохраняет только успешные действия.
- AI получает только разрешённое состояние.
- Turbo, Stimulus и UI не изменяют GameState.
- Автотесты не вызывают реальные API.
- Постоянный AI-игрок и его колоды не создаются заново на каждую партию.
- Не вводить Redis.
- Не менять PostgreSQL 12/14.
- Язык интерфейса — украинский.
- Не менять игровую механику без согласования.
- Боевые события описывают результат Engine.
- CSS и графика не должны менять правила.
- Локальные файлы пользователя важнее устаревших копий GitHub.
- Не изменять работающий код на основании неподтверждённых гипотез.
- GitHub используется только для чтения.

## Stage 21 — AI в игровом процессе (ЗАВЕРШЁН)

### AI-игрок и постоянные колоды

- Game поддерживает `pvp` и `ai`.
- `Player#ai?`.
- `AiPlayers::Setup` — постоянный AI-игрок.
- `AiPlayers::DecksSetup` — постоянные колоды.
- `Matchmaking::AiDeckSelector` выбирает совместимую колоду в пределах ±10% веса.
- Реализован сервис создания AI-игры.

### Решения и цикл

- Реализованы `DecisionProviders::AI`, Context и адаптеры.
- `GameActionRunner` проверяет digest и сохраняет успешный state.
- `Games::RunAiTurns` ограничивает количество действий и повторов.
- Используется PostgreSQL advisory lock.
- Реализован пошаговый Turbo broadcast.
- AI может начинать игру первым.
- В браузере подтверждена полноценная AI-партия.

### Groq

Используется модель:

`openai/gpt-oss-20b`

Structured Outputs со строгой схемой `action_index`.

`reasoning_effort=low`.

Модель выбирает действие из серверного списка `legal_actions`.

Предусмотрены ограниченные повторы временных ошибок и HTTP 429.

Если доступно одно действие, API не вызывается.

Символ класса не является индикатором доступности действия.

Использовать CSS или SVG.

Не встраивать символы в PNG.

### Характеристики

На нижней панели:

- огневая мощь;
- HP;
- топливо.

Значения берутся из `VisibleState`.

Правило отображения:

- `0` — существующая характеристика равна нулю;
- `–` — характеристика неприменима.

### Индикаторы движения

Количество колёс определяется `movement_limit`.

**`movement_count` содержит количество оставшихся перемещений.**

Не использовать формулу:

```text
movement_limit - movement_count
```

Для определения оставшихся перемещений применяется:

```ruby
movement_remaining =
  movement_count.clamp(0, movement_limit)
```

После выставления техники на поле:

```text
movement_count = 0
```

Поэтому только что выставленная техника не имеет подсвеченных колёс.

При перемещении GameEngine уменьшает `movement_count`.

### Цвет колёс

Утверждена система:

- собственная техника — зелёный `#32cd32`;
- техника противника — красный `#ff3030`;
- использованное или недоступное перемещение — стандартный цвет.

Для техники с двумя перемещениями:

| Состояние | Первое колесо | Второе колесо |
|---|---|---|
| Собственная техника, 2 перемещения | Зелёный | Зелёный |
| Собственная техника, 1 перемещение | Зелёный | Стандартный |
| Техника противника, 2 перемещения | Красный | Красный |
| Техника противника, 1 перемещение | Красный | Стандартный |
| Перемещения закончились | Стандартный | Стандартный |
| Техника только выставлена | Стандартный | Стандартный |

Подсветка оставшихся перемещений учитывает владельца техники и активного игрока.

Во время хода владельца отображаются его оставшиеся перемещения.

Во время хода другого игрока колёса техники неактивного владельца имеют стандартный цвет.

Индикаторы не гарантируют наличие допустимого маршрута.

### Огневая мощь

Используется тот же принцип, что и для штабов:

- `has_attacked` в ход владельца;
- `has_counterattacked` в ход противника.

Если соответствующее действие ещё не использовано:

- собственная техника — зелёная огневая мощь;
- техника противника — красная огневая мощь.

После использования соответствующего действия значение становится стандартного цвета.

Допустимость действия определяется сервером.

### Зеркальное отображение техники противника

**Статус: ВЫПОЛНЕНО.**

Собственная техника отображается в стандартной ориентации.

Техника противника зеркально отражается по горизонтали.

Цель:

- собственная техника визуально направлена вправо;
- техника противника визуально направлена влево.

Зеркальное отображение выполняется через CSS:

```css
transform: scaleX(-1);
```

Отражается только иллюстрация.

Не отражаются:

- рамка;
- название;
- символ класса;
- колёса;
- огневая мощь;
- HP;
- топливо.

Для каждого типа техники используется один исходный PNG.

Не создавать отдельные изображения для противника.

Зеркальное отображение не меняет координаты, игровые действия и правила GameEngine.

### Propshaft

При первоначальном подключении CSS-компонента наблюдалась ошибка:

```text
Propshaft::MissingAssetError:
The asset 'components/technique-field.css'
was not found in the load path.
```

После выполнения:

```bash
bin/rails assets:precompile
```

пользователь подтвердил запуск игры.

Причина первоначальной ошибки окончательно не установлена.

При повторении проверить файл, путь, импорт и конфигурацию Propshaft.

### Браузерная проверка

Пользователь подтвердил корректную работу:

- многослойного отображения техники;
- прозрачных рамок;
- динамических характеристик;
- обозначений классов;
- зелёно-красной индикации принадлежности;
- колёс движения;
- изменения колёс после перемещения;
- отсутствия подсветки перемещений после выставления техники;
- зеркального отображения техники противника.

### Критерии завершения базового компонента

Базовый квадратный компонент считается выполненным, поскольку:

- иллюстрации техники видны;
- рамки прозрачны в области иллюстрации;
- изображения и рамки совмещаются;
- обозначения классов реализованы;
- индикаторы движения соответствуют оставшимся перемещениям;
- огневая мощь, HP и топливо отображаются динамически;
- нулевые значения отображаются как `0`;
- цветовая индикация разделена по принадлежности;
- собственная техника имеет стандартную ориентацию;
- техника противника отображается зеркально;
- пользователь проверил результат в браузере.

Отдельно остаются:

- индикатор способности;
- вертикальные карты техники;
- итоговая проверка адаптивности;
- общий автоматизированный прогон тестов Stage 24.
