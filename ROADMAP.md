## Обязательные архитектурные границы

```text
Decision Provider → Action → GameActionRunner → GameEngine → GameState
```

- GameEngine — единственный арбитр правил; AI выбирает Action, но не изменяет state.
- GameActionRunner сохраняет только успешный Action и проверяет актуальность digest.
- AI получает только разрешённое состояние и серверные допустимые действия, не видит скрытые карты противника.
- Turbo, Stimulus и UI не изменяют GameState и не реализуют игровые правила.
- Автотесты не вызывают реальный API и не требуют ключей.
- Постоянный AI-игрок и его колоды не создаются заново на каждую партию.
- Не вводить Redis; не менять PostgreSQL 12/14.
- Язык пользовательского интерфейса — украинский.
- Не менять игровую механику без согласования и отражения утверждённых изменений в `GAME_RULES.md`.
- Боевые события описывают уже исполненный Engine результат. Они не становятся самостоятельными игровыми действиями и не должны побуждать UI повторно вычислять правила.
- Тематическое разделение CSS само по себе не должно изменять внешний вид или поведение игры.
- Актуальные локальные файлы пользователя важнее устаревших копий из удалённого репозитория.

## Stage 21 — AI в игровом процессе (ЗАВЕРШЁН)

### AI-игрок и постоянные колоды

- Game поддерживает `pvp` и `ai`; `Player#ai?`; частичный уникальный индекс для единственного AI-игрока.
- `AiPlayers::Setup` — постоянный идемпотентный AI-игрок.
- `AiPlayers::DecksSetup` — постоянные колоды на основе существующих карт.
- `Matchmaking::AiDeckSelector` выбирает полную совместимую AI-колоду в пределах ±10% веса и при нескольких совпадениях предпочитает ближайшую.
- Реализован серверный сервис создания AI-игры.

### Решения, применение Action и цикл

- Реализованы `DecisionProviders::AI`, `Context`, Groq/OpenAI adapters, проверка ответа и ограниченные повторы.
- `GameActionRunner` блокирует игру, сверяет digest, вызывает Engine и сохраняет только успешный state.
- `Games::RunAiTurns`: максимум 20 действий, максимум 3 stale-state retry, PostgreSQL advisory lock, остановка при смене хода, завершении, ошибке или лимите.
- `GamesController` запускает AI после хода человека и при открытии игры, если ходит AI.
- Пошаговый Turbo реализован: `Games::RunAiTurns` вызывает `on_action` после сохранения каждого AI-действия; контроллер перечитывает Game и отправляет отдельный broadcast для каждого действия и каждого игрока.
- Тестами проверены отдельные broadcasts, соответствующие events/state, скрытая информация и частичные результаты при ошибке.
- В браузере подтверждены последовательные действия и завершение полноценной AI-партии.

### Groq

Используется модель `openai/gpt-oss-20b`, Structured Outputs со строгой JSON-схемой `action_index` и `reasoning_effort=low`.

Адаптер выбирает действие из серверного `legal_actions`, не дублирует `available_actions` в передаваемом состоянии и логирует диагностические метрики. Есть ограниченные повторы HTTP 429 при распознаваемой положительной задержке и ограниченная обработка временных сетевых ошибок. Если доступно ровно одно действие, API-вызов пропускается.

Системная инструкция оставлена без сокращения по решению пользователя. Исторически наблюдались HTTP 429/TPM, HTTP 400 `json_validate_failed` в прежнем JSON-режиме и высокий расход completion tokens. Успешная браузерная партия не гарантирует отсутствия будущих сетевых ошибок и rate limit.

## Stage 22 — дополнительная надёжность AI (ЗАВЕРШЁН)

Существующие тесты `DecisionProviders::AI` подтверждают обработку корректных и некорректных ответов, нормализацию payload, защиту `player_id`, отсутствие скрытой руки противника, ограниченные попытки и обработку ошибок провайдера.

Существующие тесты `Games::RunAiTurns` подтверждают защиту от параллельных циклов одной игры, независимость разных игр, освобождение advisory lock, сохранение уже выполненных действий при последующей ошибке, соблюдение лимита действий, stale-state retry и остановку при завершении игры или смене активного игрока.

В диагностическом логировании убраны подробные данные руки AI, payload действий и тело HTTP-ошибки из соответствующих записей. Сохранены классы ошибок, token usage, `finish_reason`, HTTP-коды и доступные rate-limit headers. Дублирующие тесты не добавлялись.
