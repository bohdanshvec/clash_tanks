## Stage 24 — UI, боевые события и графическое оформление

### Цель

Подготовить интерфейс к графическому оформлению карт, техники и игровых эффектов.

Сохранить игровые правила и архитектурные границы:

**Engine определяет результат, UI отображает его.**

### Подготовка боевых событий

В `GameEngine::Attacks::CombatExecutor` формируются события:

- `shot_fired` — произведён выстрел;
- `counterattack_fired` — произведена контратака;
- `damage_applied` — применён урон;
- `technique_destroyed` — уничтожена техника.

События выстрела и контратаки содержат данные атакующего и цели:

- тип объекта;
- `player_id`;
- `card_id`;
- название;
- позицию на поле.

Событие `damage_applied` содержит:

- цель;
- фактически нанесённый урон;
- `hp_before`;
- `hp_after`.

При повреждении штаба дополнительно передаются:

- `incoming_damage` — входящий урон;
- `armor_absorbed` — урон, поглощённый бронёй взводов;
- `headquarters_damage` — урон, фактически нанесённый штабу.

В `GameEngine::Attacks::HeadquartersCombat` добавлены:

- `platoon_damaged`;
- `platoon_destroyed`.

Подробные события дополняют результат существующего действия атаки.

Выстрел и контратака не становятся отдельными игровыми Actions.

### Урон от приказов

Проверен контракт событий в:

`app/services/game_engine/abilities/damage_technique.rb`

Событие `damage_applied` при применении приказа `damage_technique` содержит:

- `source.type: "order"`;
- `source.code`;
- `target`;
- `damage`;
- `hp_before`;
- `hp_after`.

Величина `damage` вычисляется как разница HP до и после применения урона.

При избыточном уроне отражается фактическая потеря HP.

Если техника уничтожена, после `damage_applied` формируется `technique_destroyed`.

Существующие правила проверки цели, копирования состояния, уничтожения техники и отправки уничтоженного объекта в `graveyard` сохранены.

### Урон штабу при попытке взять карту из пустой колоды

Проверены реализация `GameEngine::Cards::Draw` и существующие тесты.

При попытке взять карту из пустой колоды формируются:

- `empty_deck_draw_attempt`;
- `damage_applied`;
- `game_finished` — при уничтожении штаба.

Источник урона:

```text
source.type = "empty_deck_draw"
```

Изменения в `Draw` не потребовались.

Существующие тесты проверяют рост урона при повторных неудачных попытках, завершение партии при уничтожении штаба, порядок событий и неизменность исходного состояния.

### Контракт источников урона

| Источник | `source.type` |
|---|---|
| Обычный выстрел | `shot` |
| Контратака | `counterattack` |
| Приказ | `order` |
| Пустая колода | `empty_deck_draw` |

Для `order` дополнительно передаётся `source.code`.

Существующие legacy-события `technique_attacked` и `headquarters_attacked` сохраняются.

- HP;
- топливо.

Числовые значения выводятся средствами ERB/HTML из актуального `VisibleState`.

Значения не встроены в изображения.

### Индикация огневой мощи

Во время хода владельца штаба используется `has_attacked`.

Во время хода противника используется `has_counterattacked`.

Если соответствующая атака или контратака ещё не использована, огневая мощь подсвечивается цветом принадлежности:

- собственный штаб — зелёный `#32cd32`;
- штаб противника — красный `#ff3030`.

После использования атаки или контратаки значение становится стандартного цвета.

Цвет определяется относительно игрока, который просматривает поле.

Подсветка показывает неиспользованную атаку или контратаку, но не гарантирует наличие допустимой цели.

Проверка допустимости остаётся ответственностью GameEngine.

Пользователь проверил разделение цветов в браузере.

### Очистка игрового поля



- рамки штабов со способностью;

- рамки техники со способностью;
- рамки приказов;

### Прозрачность рамок — ИСПРАВЛЕНО

### Условные обозначения классов

Реализованы:

| Класс | Символ |
|---|---|
| ЛТ | Ромб |
| СТ | Горизонтальный узкий прямоугольник |
| ТТ | Квадрат |
| ПТ-САУ | Треугольник |
| САУ | Вертикальный узкий прямоугольник |

Символ размещается в верхнем правом элементе рамки.

Цвет символа определяется принадлежностью техники:

- собственная техника — зелёный `#32cd32`;
- техника противника — красный `#ff3030`.

Цвет не зависит от того, чей сейчас ход.

Символ класса является постоянным индикатором принадлежности, а не индикатором доступного действия.

### Индикаторы движения — ВЫПОЛНЕНО

Реализованы индикаторы в виде колёс.

Количество определяется `movement_limit`.

**Важное уточнение: `movement_count` означает количество оставшихся перемещений.**

Не использовать формулу:

```text
movement_limit - movement_count
```

Она неверна для текущей модели GameEngine.

Для отображения оставшихся перемещений используется:

```ruby
movement_remaining =
  movement_count.clamp(0, movement_limit)
```

При выставлении техники на поле:

```text
movement_count = 0
```

Поэтому новая техника отображается без доступных перемещений.

При перемещении GameEngine уменьшает `movement_count`.

### Цвет индикаторов движения

Утверждена и реализована следующая система:

- собственная техника — зелёный `#32cd32`;
- техника противника — красный `#ff3030`;
- использованное или недоступное перемещение — стандартный цвет.

Для техники с двумя перемещениями:

| Состояние | Первое колесо | Второе колесо |
|---|---|---|
| Собственная техника, 2 перемещения | Зелёный | Зелёный |
| Собственная техника, 1 перемещение | Зелёный | Стандартный |
| Техника противника, 2 перемещения | Красный | Красный |
| Техника противника, 1 перемещение | Красный | Стандартный |
| Перемещения закончились | Стандартный | Стандартный |
| Техника только выставлена | Стандартный | Стандартный |

Подсветка применяется только к технике игрока, чей сейчас ход.

Во время собственного хода подсвечиваются оставшиеся перемещения собственной техники.

Во время хода противника подсвечиваются оставшиеся перемещения его техники.

Индикаторы техники игрока, который сейчас не ходит, имеют стандартный цвет.

При наступлении следующего хода владельца оставшиеся перемещения снова отображаются согласно актуальному состоянию GameEngine.

Цветные колёса не гарантируют наличие допустимого маршрута.

### Огневая мощь техники — ВЫПОЛНЕНО

Для техники используется цветовая индикация атаки и контратаки.

Используются:

- `has_attacked`;
- `has_counterattacked`.

Если соответствующее действие ещё не использовано:

- огневая мощь собственной техники — зелёная;
- огневая мощь техники противника — красная.

После использования соответствующего действия значение становится стандартного цвета.

При отображении учитываются текущий игрок и владелец техники.

Допустимость атаки остаётся ответственностью GameEngine.

### Зеркальное отображение техники противника — ВЫПОЛНЕНО

Реализовано зеркальное отображение квадратной иллюстрации техники противника.

Правило:

- собственная техника — стандартная ориентация, ствол вправо;
- техника противника — зеркальная ориентация, ствол влево.

Каждый игрок видит собственную технику в стандартной ориентации.

Для обоих игроков используется один исходный PNG соответствующей карты.

Зеркальное отображение выполняется средствами CSS.

Принцип:

```css
transform: scaleX(-1);
```

Преобразование применяется только к иллюстрации противника.

Не отражаются:

- рамка;
- название;
- символ класса;
- колёса;
- огневая мощь;
- HP;
- топливо.

Зеркальное отображение не меняет игровую механику, координаты и направление допустимых действий.

Пользователь проверил результат в браузере.

### Нулевые значения

Утверждено правило:

- `0` — существующая характеристика со значением ноль;
- `–` — неприменимая характеристика.

Не заменять числовой ноль прочерком.

### Динамические данные

Названия, характеристики и описания способностей остаются HTML/CSS и должны поступать из актуальных данных карты и разрешённого состояния.

### Критерии завершения базового графического оформления техники

Базовое оформление техники считается выполненным, поскольку:

- иллюстрации видны под прозрачными рамками;
- рамки совмещаются с изображениями;
- реализованы обозначения пяти классов;
- индикаторы движения соответствуют оставшимся перемещениям;
- характеристики отображаются динамически;
- нулевые значения отображаются как `0`;
- цветовая индикация атаки и контратаки разделена по принадлежности;
- собственная техника отображается в стандартной ориентации;
- техника противника отображается зеркально;
- основные визуальные сценарии проверены пользователем в браузере.

Остаются общие задачи итоговой проверки Stage 24, включая автоматизированные тесты, адаптивность и дальнейшее подключение других типов карт.
