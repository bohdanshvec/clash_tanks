## Страница статистики

Реализована страница `/statistics`.

### Доступ и отображение

- Гость может просматривать таблицу Top 100.
- Зарегистрированный игрок видит собственную статистику и таблицу Top 100.
- Собственная строка зарегистрированного игрока выделяется в рейтинге.
- Интерфейс страницы должен оставаться на украинском языке.

### Учёт результатов

Для игрока используются поля:

- `battles_count` — количество учтённых партий;
- `wins_count` — количество побед;
- `losses_count` — количество поражений.

`Player.statistics_leaders` формирует рейтинг по следующим критериям:

1. Победы — по убыванию.
2. Точный процент побед — по убыванию.
3. Количество партий — по убыванию.
4. `id` — по возрастанию для детерминированного порядка.

`Statistics::RecordGameResult` записывает результаты завершённых PvP-партий для зарегистрированных человеческих игроков.

**Партии против AI не включаются в статистику PvP. Партии гостей также не включаются.**

Если правила подсчёта статистики будут изменены, необходимо синхронизировать код, тесты и эту документацию.

## Stage 21 — AI в игровом процессе (ЗАВЕРШЁН)

### 1. База, модели и постоянный AI-игрок

- Режимы Game: `pvp`, `ai`; `Player#ai?`; частичный уникальный индекс для одного постоянного AI-игрока.
- `AiPlayers::Setup` идемпотентно находит или создаёт `ai@clash-tanks.local`.
- `AiPlayers::DecksSetup` готовит три постоянные AI-колоды на основе существующих карт.
- Игрок и колоды повторно используются между партиями; постоянные Deck не изменяются во время игры.

### 2. Подбор совместимой колоды

`Matchmaking::AiDeckSelector` выбирает полную AI-колоду в диапазоне ±10% веса, при нескольких совпадениях предпочитает ближайшую. Конкретные веса зависят от актуальных характеристик карт и состава колод.

### 3. AI-решение и безопасное выполнение Action

- `DecisionProviders::AI` получает разрешённый Context, проверяет ответ, нормализует ключи payload и допускает максимум три попытки некорректного решения.
- Источник решений подменяется в тестах; реальный API из тестов не вызывается.
- GameActionRunner под блокировкой сверяет `expected_state_digest`, вызывает Engine и сохраняет только успешный state.
- Устаревший или отклонённый Action не изменяет игру.
- Проверки покрывают успешное сохранение, отказ Engine, waiting, stale digest и актуальный digest.

### 4. Автоматический AI-цикл

`Games::RunAiTurns` (`app/services/games/run_ai_turns.rb`):

- максимум 20 AI-действий за запуск;
- PostgreSQL advisory lock предотвращает параллельные циклы одной игры, независимые игры не блокируются;
- максимум три stale-state retry;
- перед решением перечитывает игру и проверяет статус, активного игрока и лимит;
- прекращает цикл при смене хода, завершении игры, ошибке или лимите;
- сохраняет уже выполненные действия при последующей ошибке;
- принимает необязательный `on_action` и вызывает его с событиями каждого успешного действия после сохранения state.

### 5. GamesController и пошаговый Turbo

1. `GamesController#process_game_action` применяет человеческий Action, перечитывает игру и отправляет `broadcast_game_update(human_events)`.
2. Затем вызывает `run_ai_turns_if_needed(broadcast_each_action: true)`.
3. `Games::RunAiTurns` после каждого успешного AI Action вызывает `on_action(action_events)`.
4. Callback контроллера делает `@game.reload` и отправляет отдельный `broadcast_game_update(action_events)`.
5. Каждый broadcast формирует собственный VisibleState для каждого участника.
6. `GamesController#show` запускает AI, если открыта started-игра, в которой ход принадлежит AI.
7. Ошибка provider не отменяет уже сохранённое человеческое действие или выполненные действия AI.

Контроллерные тесты проверяли отдельные broadcasts и отсутствие передачи скрытой руки. Пользователь подтвердил последовательное отображение действий реального AI в полноценной браузерной партии.

### 6. GroqAdapter

Основной адаптер — Groq, модель `openai/gpt-oss-20b`.

- Модель выбирает `action_index` из индексируемых `legal_actions`.
- Адаптер проверяет индекс и возвращает исходное разрешённое действие.
- `available_actions` не дублируется в передаваемом состоянии.
- Используются Structured Outputs со строгой JSON-схемой `action_index` и `reasoning_effort=low`.
- Если доступно единственное допустимое действие, API-вызов пропускается.
- Предусмотрены ограниченные повторы HTTP 429 при распознаваемой положительной задержке и ограниченная обработка временных сетевых ошибок.
- HTTP transport подменяется в тестах.
- Системная инструкция `INSTRUCTIONS` оставлена без сокращения по решению пользователя.

В ходе разработки наблюдались HTTP 429 из-за TPM и HTTP 400 `json_validate_failed` в прежнем JSON-режиме. Полноценная браузерная партия с реальным Groq была сыграна успешно, но это не гарантирует отсутствия будущих rate limit и сетевых ошибок.

## Архитектурные границы

```text
Decision Provider → Action → GameActionRunner → GameEngine → GameState
browser session → current_player → GamePlayer → Action.player_id → GameEngine
```

GameEngine — единственный арбитр правил; Controller организует процесс и Turbo; AI выбирает Action; GameActionRunner безопасно применяет его; VisibleState ограничивает данные.

AI не мутирует state и не получает скрытые данные противника.

## Исследование игрового баланса и контратак

Предстоит проверить две гипотезы пользователя:

1. Первый игрок может получать преимущество благодаря раннему развёртыванию техники и атаке вражеского штаба на следующем своём ходу.
2. AI может не использовать возможности уничтожить вражеские единицы без получения ответной атаки.

Эти предположения ещё не подтверждены серией тестовых партий. Пользователь планирует сначала поиграть и собрать наблюдения.

Для проверки полезно фиксировать:

- кто ходил первым;
- составы и вес колод;
- первые развёрнутые и перемещённые единицы;
- урон штабам;
- какие защитные действия были доступны;
- какие единицы могли атаковать или уничтожить друг друга;
- была ли возможна контратака и произошла ли она;
- итог партии и номер хода завершения.

После сбора наблюдений нужно проверить `GAME_RULES.md` и фактическую реализацию Engine. Отдельно определить, связана ли проблема с правилами, стратегией AI или обоими компонентами.

**До подтверждения гипотез не менять механику и не считать изменение контратаки утверждённым.**
