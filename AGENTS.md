## Проект и обязательные границы

`clash_tanks` — учебная браузерная пошаговая карточная стратегия про танки. Проект вдохновлён WoT: Generals, но использует собственные названия, правила, карты и материалы.

Игра ориентирована на украинскую аудиторию. **Язык пользовательского интерфейса — украинский.** Новые и изменяемые надписи интерфейса, сообщения игроку, названия кнопок и тексты страниц должны быть на украинском языке. Не переводить интерфейс на русский без прямого указания пользователя.

Главный инвариант:

```text
Decision Provider → Action → GameActionRunner → GameEngine → GameState
```

GameEngine — единственный арбитр игровых правил. Controllers, UI, JavaScript, Stimulus, Turbo и AI не изменяют GameState напрямую, не определяют правила и не обходят Engine. GameActionRunner безопасно применяет Action и сохраняет только успешный результат.

Не придумывать механики вне `GAME_RULES.md`. Не изменять и не удалять PostgreSQL 12 и 14 без явного указания. При противоречии документации и кода сообщить пользователю, не выбирать самостоятельно. Не вводить Redis.

## Stage 21 — AI в игровом процессе

### AI-игрок, колоды, создание игры

- Game поддерживает режимы `pvp` и `ai`; `Player#ai?` отличает технического игрока; частичный уникальный индекс ограничивает число постоянных AI-игроков одним.
- `AiPlayers::Setup` идемпотентно находит или создаёт `ai@clash-tanks.local`.
- `AiPlayers::DecksSetup` подготавливает постоянные AI-колоды на основе существующих карт.
- `Matchmaking::AiDeckSelector` выбирает полную совместимую колоду в пределах ±10% веса и при нескольких совпадениях выбирает ближайшую.
- Реализован серверный путь создания AI-игры. В браузере проверены кнопка AI и гостевой flow.

### Решения и применение Action

- Реализованы `DecisionProviders::Context`, `DecisionProviders::AI`, Groq/OpenAI adapters.
- `DecisionProviders::AI` проверяет ответ и payload, нормализует ключи, допускает максимум три попытки некорректного решения.
- `GameActionRunner` проверяет актуальность digest под блокировкой игры, вызывает Engine и сохраняет только успешное состояние.
- `Games::RunAiTurns` ограничивает число действий за запуск, использует PostgreSQL advisory lock и повторяет решение при ограниченном числе stale-state ошибок.
- `Games::RunAiTurns` поддерживает `on_action`, вызываемый после сохранения каждого успешного действия.
- `GamesController` рассылает отдельные обновления Turbo после человеческого действия и каждого успешного действия AI.
- Каждый broadcast формирует собственный `VisibleState` для каждого игрока. Скрытые данные противника не передаются.

### Groq

Основной провайдер — Groq, модель `openai/gpt-oss-20b`. Адаптер использует Structured Outputs со строгой JSON-схемой `action_index`, `reasoning_effort=low` и `max_completion_tokens=512`.

Модель выбирает индекс серверного списка `legal_actions`; адаптер проверяет индекс и возвращает исходное разрешённое действие. `available_actions` не дублируется в передаваемом `game_state`.

Если доступно ровно одно допустимое действие, адаптер возвращает его без запроса к Groq. Системная инструкция `INSTRUCTIONS` оставлена без сокращения по решению пользователя.

В адаптере предусмотрены ограниченные повторы некоторых HTTP 429 при распознаваемой положительной задержке и ограниченная обработка временных сетевых ошибок. Логирование содержит диагностические метрики, но не должно выводить полную руку AI, подробные payload действий или тела HTTP-ошибок.

Сетевые ошибки и ограничения внешнего API всё ещё возможны.
