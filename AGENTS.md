## Проект и обязательные границы

clash_tanks — учебная браузерная пошаговая карточная стратегия про танки. Проект вдохновлён WoT: Generals, но использует собственные названия, правила, карты и материалы.

Главный инвариант:

```text
Decision Provider → Action → GameActionRunner → GameEngine → GameState
```

GameEngine — единственный арбитр игровых правил. Controllers, UI, JavaScript, Stimulus, Turbo и AI не изменяют GameState напрямую, не определяют правила и не обходят Engine. GameActionRunner безопасно применяет Action и сохраняет только успешный результат.

Не придумывать механики вне GAME_RULES.md. Не изменять и не удалять PostgreSQL 12 и 14 без явного указания. При противоречии документации и кода сообщить пользователю, не выбирать самостоятельно. Не вводить Redis.

## Stage 21 — AI в игровом процессе

### AI-игрок, колоды, создание игры

- Game поддерживает режимы `pvp` и `ai`; `Player#ai?` отличает технического игрока; частичный уникальный индекс ограничивает число постоянных AI-игроков одним.
- `AiPlayers::Setup` идемпотентно находит/создаёт `ai@clash-tanks.local`.
- `AiPlayers::DecksSetup` идемпотентно готовит три постоянные колоды: США — лёгкая техника (вес 13), СССР — средняя (22), Германия — тяжёлая (28). Используются существующие карты; отдельные записи на каждую партию не создаются.
- `Matchmaking::AiDeckSelector` выбирает полную совместимую колоду в пределах ±10% веса; при нескольких совпадениях — ближайшую.
- Реализован серверный путь создания AI-игры. В браузере проверены кнопка AI и гостевой flow.

### Решения и применение Action

- `DecisionProviders::Context`, `DecisionProviders::AI`, `GameEngine::Action`, Groq/OpenAI adapters.
- `DecisionProviders::AI` проверяет ответ и payload, нормализует ключи, допускает максимум три попытки некорректного решения.
- `GameActionRunner` проверяет актуальность digest под блокировкой игры, вызывает Engine и сохраняет только успешное состояние.
- `Games::RunAiTurns`: максимум 20 действий за запуск; PostgreSQL advisory lock защищает от параллельных AI-циклов одной игры; до 3 повторов stale state; перед решениями перечитывает игру, прекращает цикл при смене хода, завершении, ошибке или лимите.
- `Games::RunAiTurns` поддерживает необязательный `on_action`, вызываемый после сохранения каждого успешного действия, с событиями именно этого действия.
- `GamesController#show` запускает AI при открытии игры во время хода AI. После человеческого действия контроллер сначала сохраняет и рассылает человеческое действие, затем запускает AI с `broadcast_each_action: true`.
- Каждый broadcast формирует собственный `VisibleState` для каждого игрока. Проверяются отдельные события/состояния после действий и отсутствие раскрытия чужой руки.

### Groq — актуальное состояние

Основной провайдер — Groq, модель `openai/gpt-oss-20b`. Проверенная конфигурация адаптера: Structured Outputs со строгой JSON-схемой `action_index`, `reasoning_effort=low`, `max_completion_tokens=512`. Модель выбирает индекс серверного списка `legal_actions`; адаптер валидирует индекс и возвращает исходное разрешённое действие. `available_actions` не дублируется в передаваемом `game_state`.

Если доступно ровно одно допустимое действие, адаптер возвращает его без запроса к Groq. Системная инструкция `INSTRUCTIONS` намеренно оставлена без сокращения по решению пользователя.

Адаптер логирует token usage, `finish_reason`, HTTP-диагностику и доступные rate-limit headers; ограниченно повторяет HTTP 429 при распознаваемой положительной задержке. Временные сетевые ошибки также обрабатываются ограниченно.

Исторически наблюдались HTTP 429 (TPM) и HTTP 400 `json_validate_failed` в прежнем JSON-режиме. Не утверждать, что ошибки невозможны в текущей конфигурации.

## Stage 22 — дополнительная надёжность AI (ЗАВЕРШЁН)

- Проверено существующее покрытие `DecisionProviders::AI`: некорректный формат ответа, повторные попытки, исчерпание трёх попыток, исключение внешнего провайдера и невалидный индекс действия Groq.
- Проверено существующее покрытие `Games::RunAiTurns`: ошибка провайдера, невалидное действие, освобождение advisory lock, конкурентный запуск одной игры, независимость разных игр, stale-state retry, завершение игры и смена активного игрока во время решения.
- Проверено сохранение ранее успешно применённого действия при ошибке следующего решения.
- Проверено отсутствие содержимого руки противника в данных, передаваемых decision source.
- Полноценный браузерный AI lifecycle с реальным Groq был проверен ранее в Stage 21; после изменений только диагностического логирования повторять партию не потребовалось.
- Снижена детализация диагностических логов: убраны полные данные руки AI, payload действий, тело HTTP-ошибок и сообщения исключений из ряда записей. Сохранены типы ошибок и диагностические метрики, полезные для поиска проблем.
- Новые тесты не добавлялись там, где необходимое поведение уже покрыто существующими.
- Последний полный набор: `534 runs, 2031 assertions, 0 failures, 0 errors, 0 skips`.
